# T-001: Add a "Share Cheesy Scribe" row to Settings (CHEESE-71)

You are a subagent dispatched by an orchestrator. Do exactly this task, then report in the format

## Goal
Closed testers said there is no way to share the app from inside it. Add one row to the Settings
screen that opens the Android share sheet with a short message and a single link to the app's
page on tkforgeworks.com. The app must never contain a store URL: the website page sends each
visitor to the right store, so the message keeps working when the iPhone app appears.

## Expected outcome
- `lib/features/settings/share_app.dart` exports:
  - `const shareAppUrl = 'https://tkforgeworks.com/apps/cheesy-scribe/';`
  - `const shareAppMessage` = a one- or two-sentence invitation that ends with the URL, written
    for someone recommending the app to a friend. Draft (Tim reviews copy later; keep it close):
    "I keep my cheese tasting notes in Cheesy Scribe. Try it: https://tkforgeworks.com/apps/cheesy-scribe/"
  - `typedef ShareText = Future<void> Function(String text, {String? subject});`
  - `final shareAppProvider = Provider<ShareText>(...)` whose default calls share_plus
    (`SharePlus.instance.share(ShareParams(text: text, subject: subject))`).
- Settings screen: a new row at the top of the ABOUT group (before Version), key
  `SettingsScreen.shareRowKey` (`Key('settings-share-app')`), leading `HeroIcon(HeroIcons.share,
  color: x.textTertiary)` matching the other leading icons, title "Share Cheesy Scribe", subtitle
  "Send a friend the link.", trailing chevron like the neighbouring rows. Tapping calls
  `ref.read(shareAppProvider)(shareAppMessage, subject: 'Cheesy Scribe')`. Add the public
  `static const` strings for title and subtitle on `SettingsScreen` so tests reference them.
- `pumpApp` gains `ShareText? share`; when given it overrides `shareAppProvider`; when omitted the
  override fails the test on any call (`fail('Unexpected share: $text')`), mirroring the
  `feedbackHttp` default.
- One new `testApp` test: the row is present with its title; tapping it calls the fake exactly
  once with a text that contains `shareAppUrl` and nothing that looks like a store URL
  (`expect(text, isNot(contains('play.google.com')))`). Follow the viewport setup of the
  existing tests.
- No other screen or behaviour changes.
